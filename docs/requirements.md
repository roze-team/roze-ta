# roze-ta 技术分析库需求规格说明书

版本：V0.2 需求草案  
日期：2026-09-03  
目标：在 Yata 基础上建设可复现、可扩展、可审计的纯 Rust 技术分析库。

扩展规格：[指标扩展清单](indicator-expansion.md)、[机器可读任务表](indicator-backlog.csv)、
[概率与统计分析需求](probability-statistics.md)。

数学背景与公式说明见[金融数据分析的数学基础](mathematical-foundations.md)，不作为新增能力已实现的声明。

FR-IND-009 与 AC-IND-009：[外部指标逐项覆盖需求](reference-indicator-parity.md)。外部库已有指标逐项核对与实现，原 84 项清单不再作为覆盖上限；完成状态以逐项映射及验收证据为准。

本文描述目标需求和验收条件，不表示所有功能已经实现，也不授权部署、发布或真实交易。

## 1. 项目定位

`roze-ta` 负责将有明确时间和来源的行情数据转换为结构化技术分析结果。
同一计算逻辑供历史回测、实时策略、证据包和 MCP 使用。

```text
已收盘行情 / 指定历史快照
    → 数据校验与时间对齐
    → 确定性指标计算
    → 特征组合与市场状态描述
    → 带版本、质量状态和哈希的结果
        ├─ Rust 原生接口 → market-compute-service → 不可变证据包
        └─ MCP 接口 → AI / 外部分析客户端
```

Roze 业务服务直接调用 Rust 库。模型调用、开平仓决策、账户风控和订单执行属于上层交易系统。
指标输出中的技术信号不等于可执行订单，不携带账户权限。

## 2. 核心目标与边界

必须实现：

1. 纯 Rust 构建，不强制依赖 Python、TA-Lib C 库、数据库或 Roze 服务运行时。
2. 批量计算与逐根更新使用同一条计算路径。
3. 每项指标明确公式变体、参数、单位、预热和时间对齐规则。
4. 输入不合法、预热不足或结果未定义时返回可区分状态，不能伪造有效数值。
5. 计算结果可追溯至输入、实现、配置和运行环境。
6. 保留上游源码、许可证、版本和补丁记录，可独立构建与升级。
7. MCP 与 Rust API 返回语义一致的结果，支持目录发现和有界批量计算。

本项目不负责：券商连接、行情采集服务、资金管理、实盘下单、AI 策略选择、自动经验晋升。
不以指标数量作为唯一完成标准，不把同一指标的不同周期重复计算为不同指标。

## 4. 指标覆盖需求

覆盖目标扩展为 **60 类核心指标、12 类形态规则、12 类结构/多周期特征**。
按 A 批 40 类、B 批追加 20 类、C 批追加形态与结构能力推进；当前 23 类原型不等于目标已完成。
具体 ID、当前基础与批次以 [指标扩展清单](indicator-expansion.md) 为准。
概率与统计作为独立能力层纳入本项目，描述统计、分布、回归、统计检验、条件概率、
贝叶斯更新、重采样、蒙特卡洛及概率校准见 [专项需求](probability-statistics.md)。
其中基础滚动统计复用同一 ID，不与核心指标清单重复计数。

| 编号 | 类别 | 第一阶段范围 | 扩展范围 |
| --- | --- | --- | --- |
| FR-IND-001 | 均线与平滑 | SMA、EMA、WMA、RMA、HMA、KAMA | DEMA、TEMA、VWMA及其他已审查方法 |
| FR-IND-002 | 趋势与方向 | ADX/DI、Aroon、SAR、Ichimoku | SuperTrend、回归斜率、趋势持续性 |
| FR-IND-003 | 动量与振荡 | RSI、MACD、Stochastic、CCI、CMO、MFI、AO、Yata TRIX 变体 | ROC、TSI、RVI、其他上游振荡器 |
| FR-IND-004 | 波动与通道 | TR、ATR、标准差、布林带、Donchian、Keltner | NATR、历史波动率、波动率分位数 |
| FR-IND-005 | 量价 | CMF、Chaikin Oscillator、EFI | OBV、会话 VWAP、锚定 VWAP、相对成交量 |
| FR-IND-006 | 统计与时间序列 | 极值、均值、变化率、标准差 | Z-score、滚动相关、分位数、回归 |
| FR-IND-007 | 市场结构 | 明确峰谷确认时刻的 Swing/Pivot | 突破/假突破、支撑阻力、区间宽度 |
| FR-IND-008 | 形态与组合 | 独立规则和版本契约 | K 线形态、背离、趋势/震荡特征组合 |

第一阶段仅承诺经过审核的核心集合。上游“36 个指标模块”不含所有基础 Method，
也不表示每个模块都应立即对 MCP 开放。对已有交易策略形式的上游模块，应明确其输出是规则信号。

每个正式指标必须附一张规格卡：

- 稳定 ID、名称、分类、描述、公式变体及参考来源。
- 实现来源与代码版本；输入字段、价格源、参数 Schema、参数范围。
- 输出字段名、顺序、单位、取值范围及异常语义。
- 初始化方式、最少样本数、建议预热、复杂度与内存上限。
- 多周期/位移语义、零成交量行为、常量序列行为。
- 基准样本、独立参考值、容差和差异说明。

不能仅凭相同指标名称断言与 TradingView 或 TA-Lib 数值兼容。
已确认的审核重点：Yata 的部分振荡器使用 0～1；CMO 使用 -1～1；
Keltner 返回值顺序需以代码核对；Yata TRIX 使用三重平滑值的绝对差分，不能标为标准百分比 TRIX；
Ichimoku 的 Senkou 输出涉及内部窗口延迟，必须说明返回时刻与图表位移的关系。

## 5. 输入与数据质量

| 编号 | 要求 | 验收条件 |
| --- | --- | --- |
| FR-DATA-001 | 输入标识包含 instrument、timeframe、来源和数据版本 | 不同数据版本不会被误认为同一快照 |
| FR-DATA-002 | 时间使用 UTC 毫秒，明确 bar 起止、已收盘状态与可知时间 | 未来数据及尚不可知的 bar 不进入 as-of 计算 |
| FR-DATA-003 | 校验有限数、OHLC 一致性和成交量 | NaN、Infinity、反向高低价被拒绝 |
| FR-DATA-004 | 价格域由数据类型明确声明 | 正价格行情为默认；负价格/价差序列必须使用显式支持的输入策略 |
| FR-DATA-005 | 明确 volume 为真实成交量、tick volume 或缺失 | 依赖 volume 的指标不能把缺失数据视作零成交量 |
| FR-DATA-006 | 校验排序、重复、缺口与交易日历 | 重复/乱序有明确错误；缺口按配置拒绝或报告，不默认补平 |
| FR-DATA-007 | 历史修正与当时可见数据分离 | 修正生成新数据版本，既有证据不可被覆盖 |
| FR-DATA-008 | 输入限制可查询 | 超出 bar 数、Profile 数、字节数或参数范围时明确失败 |

行情数据源和交易日历由调用方提供或通过显式接口注入。核心库不能隐式联网补数据。

## 6. 统一计算与状态

### FR-CALC-001 批量接口

支持单指标、多指标、最新值及完整序列计算。共同的输入校验失败应拒绝整个请求；
个别指标预热不足或数学未定义可返回该指标状态，其他结果仍可用。
调用方可选择必须全部成功的模式。

### FR-CALC-002 流式接口

每个正式指标支持 `new(config)`、`update(closed_bar)`、`latest()`、`reset()`。
同一根已收盘 bar 不得被静默重复消费。首根样本如何用于初始化和更新须一致且有测试。

### FR-CALC-003 一致性

批量回放、逐根输入、切段后恢复，在相同 Profile 和环境下得到相同结果。
涉及浮点的平台差异使用规格卡的容差验证，不承诺跨 CPU、编译器、架构逐位一致。
有损状态序列化不允许作为恢复格式。

### FR-CALC-004 状态快照

快照包含 schema_version、indicator/profile/implementation 版本、参数哈希、
最后消费时间、输入序列身份和内部状态。恢复时验证兼容性与完整性；
不兼容快照明确拒绝并提示从历史数据重建。

### FR-CALC-005 时间对齐

多周期计算只引用决策时刻已收盘且已可知的高周期数据。Pivot 的发生时刻与确认时刻分开保存。
绘图位移不能改变数据实际可用时间，禁止把未来确认结果回填为当时已知信号。

### FR-CALC-006 参数治理

首先提供固定版本 Profile，再开放受 Schema 约束的参数实例。
拒绝未知参数、超范围周期、整数截断和任意代码执行。
参数修改产生新版本或参数哈希，不覆盖已有 Profile 内容。

## 7. 结果与证据契约

统一结果至少包含：

```text
schema_version / implementation_id / implementation_version
indicator_id / profile_id / profile_version / parameter_hash
snapshot_id / data_version / input_hash / output_hash
as_of_ms / last_bar_closed_at_ms / available_at_ms
status / values / units / samples_seen / minimum_samples
quality_flags / error_code
```

FR-EVD-001：状态至少区分 ready、warming_up、invalid_input、undefined_result、unsupported。
原型 `insufficient_data/failed` 到正式状态的迁移必须通过 Schema 版本完成。

FR-EVD-002：数值未定义时保留错误状态，不能用 0、上一有效值或字符串 NaN 冒充当前结果。

FR-EVD-003：规定规范化序列化，固定字段顺序、浮点编码和 -0.0 等规则，写出哈希协议及测试向量。
输入哈希反映内容身份，输出哈希反映计算结果和实现身份。

FR-EVD-004：哈希用于内容一致性校验，不能单独证明行情真实、来源可信或数据从未被管理员修改。
签名、外部时间戳和权威账本由上层服务提供。

FR-EVD-005：核心结果不带随机值、系统当前时间或请求 trace；运行耗时、请求 ID 等放在外层日志中。
同一有效输入的数值不能随调用方式改变。

## 8. MCP 与原生接口

P0 必须保留以下两个只读工具：

| 工具 | 输入 | 输出 |
| --- | --- | --- |
| indicator_catalog | 可选分类/能力过滤，后续版本支持分页 | 指标/Profile、参数、单位、最少样本、版本和能力 |
| indicator_batch_calculate | 快照身份、as-of、bars、Profile 列表 | 与原生接口一致的结构化结果 |

FR-MCP-001：MCP 适配器必须调用核心库，不能复制公式或维护独立参数默认值。

FR-MCP-002：使用官方 Rust SDK；发布 JSON Schema、稳定错误码、协议版本和兼容策略。

FR-MCP-003：stdio 的 stdout 仅用于协议，日志写 stderr；工具声明只读、不执行交易。

FR-MCP-004：请求、响应和计算规模均有上限；调用前完成校验；长任务支持超时与取消。
流式实例句柄、缓存、远程连接属于后续能力，不能让本机批量工具隐式持有交易状态。

FR-MCP-005：如后续提供 HTTP，必须另外落实身份验证、租户隔离、配额和审计。
本机 stdio 通过不代表远程服务安全验收通过。

FR-MCP-006：计算参数和数据只能作为数据处理。拒绝动态 Rust/Python/脚本代码、任意路径或命令参数。

## 9. 特征组合与市场状态

P2 增加独立模块，把指标结果组合为可解释的确定性分析：

- 趋势方向、趋势强度、波动水平和流动性代理特征。
- 高低周期方向一致性、指标冲突与缺失情况。
- 突破距离、区间位置、已确认峰谷、价量背离等。

每个组合算法必须版本化，保存输入结果引用、规则命中及失效原因。
阈值属于显式配置，不由模型临时生成后直接执行。
输出是技术特征和状态描述，不是保证盈利的判断，也不代替独立验证。

## 10. 可扩展性与源码管理

FR-ENG-001：保留 `vendor/yata` 的原始名称、作者、Apache-2.0 许可证和来源记录。
外层 roze-ta 扩展使用自己的包名及许可证；不得把上游代码改标为自身原创。

FR-ENG-002：优先在外层扩展。确需改上游时，记录问题、最小补丁、测试和升级影响；
来源清单应区分原始文件与本地补丁。

FR-ENG-003：新增指标须经过规格卡、实现、参考值、边界测试、目录注册和文档六个步骤。

FR-ENG-004：结构允许增加其他纯 Rust 实现作为可选引擎，但结果必须标明来源，不能无提示切换公式。

FR-ENG-005：`roze-quant` 初期仍使用其现有版本。只有兼容性测试和明确依赖升级完成后，才切换到 roze-ta。

### FR-ENG-006 原生维护与迁移

算法应由 `roze-ta` 内部模块直接编译，取消对 Yata crate 的构建依赖；原始 vendor 基线与摘要应保留。
派生代码必须记录来源、修改声明、许可证和独立补丁清单；迁移不得用新摘要覆盖原始基线。
既有原生 API 路径及 `roze_ta::yata::*` 兼容路径应保持类型一致；固定 f64/u8 和序列化布局，禁止 unsafe。
验收应使用迁移前真实生成的全部 Profile 快照核对二进制内容、checksum、恢复输出，以及原有 MCP 一致性测试。
不将目录迁移视为新公式交付或全部低层 API 的错误处理审计完成。

## 11. 性能与工程质量

1. 为每项指标标明更新复杂度与状态大小；滑动窗口允许 O(period) 存储，不能笼统承诺全部 O(1) 内存。
2. 建立 release 模式基准：单指标更新、多指标批量、状态恢复和 MCP 编解码分别测量。
3. 测试覆盖 1 个/100 个/1000 个独立序列，以及 1/10/全部已注册 Profile。
4. 报告 CPU、OS、Rust 版本、构建参数、数据规模、吞吐、p50/p95/p99 和峰值内存。
5. 先建立实测基线；正式性能门槛应基于目标机器确认，不能预先宣称微秒延迟或百万吞吐。
6. 不同实例不能共享可变指标状态；并发调用不能污染输出。
7. Windows/Linux 构建和测试为首批目标；其他架构需单独验证。
8. 锁定依赖，维护许可证清单；生产 feature 默认不启用未经验证的 unsafe 性能选项。

## 12. 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| AC-001 | 批量/流式/恢复 | 同一输入，结果在声明的精度策略内一致 |
| AC-002 | 公式参考值 | 每个正式 Profile 有独立参考值；明确初始化与公式差异 |
| AC-003 | 边界输入 | 空、短、常量、单调、交替、零量、极值、NaN/Inf、乱序均有明确行为 |
| AC-004 | 时间隔离 | 追加未来数据不改变过去时点的可知结果；修正数据使用新版本 |
| AC-005 | 目录完整性 | 每个可发现 Profile 可计算；字段、单位、参数与代码一致 |
| AC-006 | MCP 一致性 | 握手/发现/调用成功，结果与原生计算一致，超限/非法请求正确拒绝 |
| AC-007 | 快照恢复 | 重启恢复不重复消费；损坏/不兼容状态拒绝 |
| AC-008 | 依赖集成 | roze-quant 原有策略回归测试通过，变化有说明，未自动触发实盘 |
| AC-009 | 来源与许可 | 上游 tag/commit、源码校验和许可证完整，可复现构建 |
| AC-010 | 发布质量 | 文档、测试、变更记录、构建产物和兼容说明一致 |

不能只用封装与同一封装对比作为公式正确性的证据。独立参考应来自已审查公式、手工小样本或明示变体的参考实现。
